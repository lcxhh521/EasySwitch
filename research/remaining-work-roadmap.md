# EasySwitch 剩余工作的实施方案

更新：2026-10-07。建议先继续能独立验证的源码工作，同时把真正需要产品选择、客户端支持和真机条件的部分拆清楚。这里没有把“本轮测试通过”当成全项目完成。

目前清单有 **27 条未关闭，另 1 条暂缓**；其中一些条目描述同一功能的不同交付或验收。最新界面第一批已经有代码，但尚无 Claude 评审通过记录；因此第二批界面不抢跑。其余独立开发不受这道关口影响。

## 二、ChatGPT 桌面增强：恢复原生并排体验

### 问题与推荐

把令牌放进本地 URL 虽能送到网关，但官方客户端会记录完整 WebSocket URL。仅清理 EasySwitch 日志无法消除这条泄漏路径。改用 stock 自定义 provider 的请求头有官方源码依据，可是 provider ID 还影响历史筛选和恢复，不能无声切换后假定原生体验没变。

推荐采用**保留原生 provider ID 的小补丁适配版 app-server**，仅在这一轮增强启动中使用。URL 不含秘密；单次权限经私有文件或继承句柄交给适配进程，仅向精确本地网关附加专属请求头。厂商登录仍由原生客户端处理，本地权限不发给厂商。适配版是额外维护的软件，不伪装成未经修改的官方发行版，也不改用户应用包或历史文件。

| 选择 | 好处 | 代价 | 建议 |
| --- | --- | --- | --- |
| 等官方支持内置 provider 的附加头 | 不承担客户端补丁维护 | 功能要继续等待，时间无法保证 | 不愿维护适配版时采用 |
| 使用 stock 自定义 provider | 配置式接入，运输已有依据 | 历史/恢复/退原生语义改变，诊断输出还需约束 | 只做隔离研究，不默认开启 |
| 维护固定版本的小补丁适配版 | 能保留原身份并控制秘密输出 | 增加版本、构建、签名和桌面兼容维护 | 推荐完整路线，先确认维护责任 |

### 实施和验收

1. 锁定桌面、客户端和适配版版本组合，限定补丁为本地鉴权输入、受限附加头及秘密输出保护。
2. 实现单次启动所属进程、令牌和连接的登记；失败和退回原生只撤销本次资源，不影响其他窗口。
3. 先完成 HTTP：无权限不能读来源 Key 或本地模型目录；原生仍只用调用方厂商凭据；禁止重定向与本地权限外泄。
4. WebSocket 需解析有界完整消息，每次生成前重新检查权限和预算；每个 response 单独结算，断流/缺用量保持未知。不能恢复旧的无解析字节管道。
5. 撤销、到期和退出必须关闭空闲或繁忙连接；不能等下一帧才失效。
6. 先跑合成身份、日志捕获、假时钟、loopback 和假启动器；再验证 Mac 内置版本、旧历史、恢复与退原生，最后才是用户在场的实际模型验收。

完整证据、八路线比较和验收矩阵见 [ChatGPT 增强安全方案](chatgpt-enhancement-safety.md)。当前未制作或运行适配版，也未放开增强/WS 权限。

## 三、只读并行：让真实 agent 安全审查材料

### 推荐架构

第一阶段只读用户明确选入的材料，先做固定文字材料审查，再做可检索的不可变快照。真实执行候选优先考虑 Claude Agent SDK 与 CodeBuddy CLI；每个候选仍须固定版本并通过隔离验收，不能把这个推荐直接当成安装或账号授权。

执行分为四层：

- **材料层**：只保存已选文件的独立副本和清单，限制路径、数量和字节；不把原仓库或 HOME 交给客户端。
- **工具层**：最多提供列文件、按文件 ID 读行、字面量搜索。处理器没有任意文件路径、Shell、网络或动态工具注册能力。
- **隔离层**：约束整个客户端及其后代的文件和网络访问；私有 HOME、只读提示词、空 tools 或普通进程组本身都不够。
- **模型代理层**：上游 Key 留在宿主，客户端只持本任务的短期权限；每次请求走现有模型/预算/任务归属，取消时失效并等待执行实例退出。

轻量路线可评估固定版本的官方 sandbox runtime；已有可信容器或 VM 也可做后端。两者都属于明确可选组件，不能为了通过测试关闭系统保护、放宽隔离或在失败后降级裸 CLI。首批不依赖用户 Codex 登录或额度。

### 最小步骤和验收

1. 用输入字节和逻辑路径实现材料清单及三个纯只读工具，先不读取真实项目。
2. 用假 worker、假模型代理接已有并行任务/费用/取消；验证跨任务访问、路径穿越、恶意工具、预算、到期和迟到结果。
3. 在获准且具备前置能力的环境运行自写隔离探针，验证宿主文件、网络、Unix socket、子进程和逃逸尝试确实受限。
4. 固定真实客户端，仅连接假上游，验证启动时的 hooks/plugins、工具集及取消；此项仍需要相应环境和执行授权。
5. 最后在用户指定材料、来源和费用上限内验收真实模型。未通过时生产注册表仍关闭，并明确说明缺哪一项。

完整客户端依据、方案取舍和逐阶段检查见[真实只读 Agent 路线](readonly-agent-execution-plan.md)。这会完成真正的 agent 执行能力；两次普通模型请求不能冒充两个真实 agent。

## 四、Grok 与 Cursor：先分清想交付哪种能力

两家现都有官方 agent 会话路线。推荐先考虑官方 ACP 任务接口，Cursor 的自定义工具再评估官方 Bridge。核心可保留零 npm 运行时依赖，厂商 CLI/Bridge 由用户明确选择并固定版本。

但这解决的是“让 Grok/Cursor agent 做一个任务”，**不是**原先“把订阅当通用模型来源给其他 agent 用”。Cursor 内置的读文件/编辑/运行命令也不能只改字段名，就成为外部调用方执行的 Chat tool_calls。

| 产品目标 | 推荐入口 | 需要额外完成的事 |
| --- | --- | --- |
| 通用 Grok 模型与函数调用 | 已有官方 xAI API 来源 | 确认 API 凭据与计费，不能假定自动消耗订阅 |
| 官方 Grok/Cursor agent 做任务 | 官方 ACP，必要时 Cursor Bridge | 初始化/权限/交互/取消、可选运行时、私有环境、用量与预算边界 |
| Cursor agent 变成跨请求工具网关 | 新的有状态来源类型 | run/会话/工具回调映射、权限、等待、去重、重启终止与费用语义，不能沿用旧文字来源身份混装 |
| 原生 token 文件转私有代理、旧 exec 全族映射 | 当前仍缺已核实合同 | 不能猜字段、借用登录或据官方 SDK 文档宣称私有接口已获支持 |

如果选择官方任务路线，先实现不带默认 spawn/auth/network 的控制器，再用 fake 接现有 TaskRuntime，最后验收可选真实运行时。只选择握手实际公布的认证方式，权限默认拒绝；取消必须等终态和所属进程关闭。

厂商 agent 内部可能直接进行多轮模型请求。单次启动前检查预算不等于逐次拦截；缺少可靠拦截点时，硬停止预算模式应拒绝该能力，不自动降成软预算。详细方案见[Grok/Cursor 官方路线](grok-cursor-official-routes.md)。

## 五、三项需要明确的产品选择

这些选择不授权安装、登录或真实调用；只是确定下一阶段应写哪条实现。

1. **ChatGPT 是否承担自有适配版的维护？** 推荐接受固定版本、最小补丁路线，换取原生身份/历史兼容；若不接受，则等待官方等价接口，不能选有泄漏的 URL 方案凑完成。
2. **只读并行是否引入可选、固定版本的隔离执行组件？** 推荐先支持用户所选材料，逐步增加快照检索；核心保持轻量，未具隔离条件的环境明确不可用。组件安装、平台权限和真实客户端验收另行处理。
3. **Grok/Cursor 第一阶段是否接受“官方 agent 任务”的交付？** 推荐先交付这一层，并把原订阅模型源/私有工具网关目标继续单列；若必须保持原目标，则继续做独立会话式网关设计和合同核查，不改名冒充完成。

真正进入账号或模型验收前，还要明确运行环境、所选材料、接收来源、认证方式和测试费用上限。当前开发可以继续做源码和假服务验证，不需要现在交出凭据。
