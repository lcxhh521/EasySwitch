# M07：OpenCode 自定义 API 来源的显式导入

用户2026-11-02要求继续 EasySwitch。本批属于既有B128/M07，不另建需求清单。独立候选叠加尚未推送的冻结M06；不修改M06产物，不推送、不访问用户电脑、不读真实配置/账号。

## 依据与完整流程

核对官方 [Providers](https://opencode.ai/docs/providers/) 与 [Config](https://opencode.ai/docs/config/)（2026-11-02访问）：OpenCode自定义来源可在配置中声明适配器、地址和模型；JSON/JSONC全局配置与独立认证文件、项目及其他配置来源分开。此批只迁移明确支持的全局自定义兼容API来源，不声称复制OpenCode合并后的运行配置。

使用已有「从其他工具导入」流程：选中「OpenCode 自定义 API 来源」→读取所选配置→脱敏预览→勾选具体条目→确认导入。新来源保持关闭，用户核对后自行开启；无自动目录查询、推理、插件或客户端启动。打开面板/勾选来源本身不读取文件。

## 边界与保护

- 仅固定 `~/.config/opencode/opencode.json` 或 `opencode.jsonc`。同时存在时拒绝猜测合并，需先明确一份配置；本批不读取项目、环境指定路径或远程配置。
- 仅支持 `@ai-sdk/openai-compatible`、字面量 `baseURL`/`apiKey`、模型ID；模型显示名称不迁移。额外头、模型映射、未知适配器或其他改变请求语义的字段不静默丢弃，条目阻断并说明。
- 不读 `auth.json`、OAuth/订阅登录，不解析环境/文件引用、命令或插件。JSONC只作数据解析，不执行代码。
- 预览不给出密钥；选中确认复用既有引用ID、过期和配置变更保护。来源文件始终只读，保存失败保留既有回滚与不确定清理提示。
- 所有开发测试只使用临时HOME中的合成文件与内存密钥；不证明真实OpenCode/macOS/供应商验收。

## 共用保存流程的必要加固

为避免导入等待钥匙串时发布半批来源，所有新凭据先暂存；最终再核对源文件指纹与新ID不存在，然后不跨异步等待地发布来源。失败清理只处理仍匹配本次写入的来源/密钥，发现并发修改或清理无法确认时保留并明确告知，不称完全回滚。UI网络错误改为「结果未确认，可能已保存，先检查，不直接重复导入」。

该保护针对应用内异步请求窗口，不声称原生钥匙串跨进程原子事务：通用SecretStore没有compare-and-swap，其他原生进程在删除调用内部改密钥的竞争仍无法由该接口绝对排除；未进行真实Keychain实验。其他导入来源的成功格式保持不变，共用保存与错误提示纳入完整回归。

窄屏验收发现原导入网格的最小内容宽度会裁掉长名称/地址和范围说明。本批加入仅作用于导入面板的可收缩单列布局与长文本折行，未改全站布局或源数据；以修复后的实际截图复验为准。
