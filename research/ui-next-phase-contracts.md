# 后续界面批次的数据与入口合同

日期：2026-10-07。基于已推第一批外壳及现有核心接口核对。本文仅准备 B101–104 的实施和测试，不修改生产页面，不表示第一批已通过 Claude 评审。逐批关口保持：上一批被评审通过后，才写下一批页面。

## 共同规则

- 核心返回状态、时间窗口、完整性及原因；前端负责呈现，不根据颜色、名称或过期的缓存猜权限。
- 新增概览/汇总 GET 不应启动 agent、签发令牌、读取原生登录、刷新厂商账号或触发模型探测。新汇总接口应使用已有内存/本地账本元数据，不为显示数字调用来源。
- 源名、模型、任务文字、账号标签等全部转义；错误沿用固定三件套与受限详情。来源错误正文不进入新面板。
- `unknown`、`off`、`blocked`、`not-connected`、`cleanupPending` 等不可统一画成“正常”。缺失值不能补零、满额或已完成。
- 轮询保留输入、选择、展开状态和键盘焦点；正在清理时即使 running=0 也继续更新。按钮双击只发生一次动作。
- 所有调用继续使用原有权限边界和明确动作。改布局不意味着重开 ChatGPT 增强、Claude Desktop 或真实只读并行。

## B101：总览页

### 一句话派活

复用 `POST /api/tasks`，保持 agent/auto、task、model、effort、cwd 的已有优先级。保留现有优先级：显式模型优先，其次规则指定模型、该agent绑定，最后才是现有catalog的首个可用模型；不额外挑一个所谓“最便宜”的来源。空输入、不支持的 agent、没有模型、预算停用及取消错误沿用已有处理。

没有来源时仍显示首次使用向导。该向导里的订阅登录、添加来源和检测动作必须继续由用户选择，不能因为总览自动打开而发起。

### 三组数字与所需证据

| 页面含义 | 现有数据 | 实施时应采用的合同 | 不能拿来替代的值 |
| --- | --- | --- | --- |
| 正在使用外接模型的会话 | `gatewaySessions`只有签发/到期元数据；`sessionDetails`是进程表观察 | 需要在真实外接推理开始/结束处维护在途计数，按已鉴权session ID去重；只统计当前在途，标明观察范围 | 有效令牌总数、最近100条日志、按进程标记猜到的PID都不是正在推理会话数 |
| 可用来源及待处理项 | Store来源、catalog、预算状态、健康快照、已知额度 | 明确显示“可选来源”；off、预算阻断、明确不可用分别计数。未知健康保留未知说明，不能证明推理可用 | 一次模型列表成功不能证明推理/工具正常；hasKey布尔值不代表凭据未过期 |
| 本月估算与预算 | 增量 `Ledger.budgetSummary`；全局预算有UTC日/月窗口 | 本月汇总用明确UTC日历月；预算按其真实日/月窗口单列进度和时间。返回未知费用/账本不完整状态 | 不能把最近30天叫本月，不能用本月总价除以日预算，也不能用截断的 `Ledger.read()`做完整累计 |

本月汇总同时保留subscriptionCalls，并写明订阅月费未计入。只有订阅调用的月份可能出现已记录按量估算为零、unknownCostCalls也为零；这不代表任务免费或没有消耗订阅额度。显示货币沿用已有显示设置，账本仍保持美元。

在途会话计数是目前需要补齐的后端元数据，尚未实现。建议只记录随机请求ID、可信session ID、agent、实际模型、开始时间与在途数；不保存正文或令牌。进入来源适配器后登记，成功、失败、取消、断流及异常均幂等结束。模型列表、MCP、count_tokens及普通原生模型转发不计入“外接推理”。同一会话并发请求只算一个会话，但列表可说明同时使用多个模型。

这个统计证明“现在有被网关观察到的外接请求”，不证明客户端窗口一直活着。不能为了列表有数字，把闲置且尚未到期的令牌叫运行中。若评审要求显示所有空闲增强窗口，需要另行补客户端生命周期证据；不能用无头匿名心跳替代权限。

### 正在运行列表

- 后台任务复用 `TaskRuntime.snapshot()`，保留父子关系、elapsedMs、usage及cleanup状态。
- 增强会话使用上述可信在途元数据；已知的任务请求按task/session关联，不把同一任务重复计为两条“新工作”。可在该任务行说明它的模型请求。
- 费用显示“已记录估算”；进行中请求尚无最终usage时明确仍有未知。父任务树费用已包括子任务，不能再加一次。
- 现有网关会话令牌管理仍保留，名称与用途独立于正在运行列表。

### 订阅额度

只列开启的订阅来源；数字和恢复时刻只能来自已读取且可识别的厂商报告。Copilot等未连接读取器的显示未接入；格式不认识显示未知。厂商没报恢复时刻时，已有30分钟等待只写“可重试时间，恢复未知”，不能画成确定几点恢复。概览不能自己额外查询厂商以补齐卡片。

### 建议接口形状

可新增一个只读汇总入口或给现有接口增加经过命名的汇总字段，选择由实施时按代码结构决定，不改上面语义。最小内容是：snapshotAt、计数的证据范围、在途会话、TaskRuntime快照、可选/待处理来源、本月增量摘要、全局预算窗口、开启订阅的既有额度状态。

该入口须受控制台请求头/Host保护。不要直接复用目前较重的 `/api/state` 路径来新增数字，因为它还会读 SecretStore 的 hasKey、查找客户端并检查原生登录。汇总元数据不需要这些副作用。也不要调用会 `drainTransitions()` 的健康提醒接口，使总览消费掉菜单栏的一次性提醒。

## B102：Agent 卡片与右侧详情

保留稳定agent ID，卡片布局不重写启动判断。已安装和可接入分别呈现；未检测到/缺启动器/手动配置/仅按文档不能都变成“可启动”。

| 旧入口 | 新位置 | 必须保留的动作或语义 |
| --- | --- | --- |
| 主模型选择器 | 右侧详情主模型 | 原生选项、来源分组、搜索、模型池和精确模型ID；关闭/预算阻断来源应不可新选，见下方现有缺口 |
| `agentControls` | 详情思考/后台/子agent区 | 模型与agent档位交集、off/none别名、未知档位编辑、主模型和各tier独立配置 |
| 备用模型 | 详情高级设置 | 显式选择、发送前切换、无备用保持原行为；不静默纳入tier或模型池 |
| 能力小圆点/覆盖表 | 详情的可读句子及保留的完整信息入口 | verified/documented/manual/todo/impossible/na区别和原因不可丢；不能把文档实现改标实测 |
| 启动/原生/打开/手动指南 | 详情操作区 | 原先支持的每一种入口仍可访问；复制命令不自动运行、不在摘要重新泄漏令牌 |
| 方案保存/应用/删除 | 页头方案按钮 | 保留全部agent设置与现有覆盖语义，不保存秘密；失败不假称已应用 |
| 实验桌面能力 | 可展开实验区或对应详情 | 当前生产阻塞和清理状态保留，不因卡片样式变了恢复按钮 |
| 网关令牌管理 | 有明确入口的管理区 | 保留列表、到期、撤销及不重新显示秘密；签发沿现有启动/手动指南流程和API，不假设已有独立签发表单 |

当前openPicker仍遍历state.providers，未普遍过滤off或预算阻断来源；后端会拒绝实际不可用模型，但选择器可能先让用户保存无效绑定。这是已确认的迁移缺口，不应写成现成过滤已经实现。实施时要保留“当前绑定已失效”的显示，同时阻止新选不可用项。

右侧详情随当前选中agent更新，不因3秒轮询跳回首个agent。若所选模型来源被关闭、删除或预算停用，显示原选择及不可用原因，要求用户明确重选，不自动改绑定。

## B103：统一模型页

全部/订阅/模型池是同一份来源集合的视图。普通API来源、专用订阅来源、文字桥、Vertex模式和模型池仍各有自己的认证/协议合同。分段过滤不能把同一账号和它的来源重复显示为两份可用额度。

需要按稳定来源ID及其已有账号关联字段去重，不能按邮箱、显示名或相似模型名合并。原设置页里的本机原生客户端账号管理与模型来源订阅不是同一数据，不因标签相似移走或合并登录。

| 必留入口 | 合并面板的要求 |
| --- | --- |
| 普通预设/手工Key/粘贴解析 | 保留预设说明、URL参数、Key池、创建错误与已保存来源处理；不读用户剪贴板直到明确动作 |
| 专用订阅登录/取消/刷新/移除/开关 | 保留各自接口、默认关闭、作用对象和真实兼容提示；打开添加面板不开始登录 |
| Vertex三种模式 | 服务账号与手动token/Express明确分开；不凭字段相似混用秘密或协议 |
| 文字桥 | 明确实验性/只文字、二进制检查、地区、默认关闭；Droid继续显示生产未可用 |
| 配置导入 | 先选来源，再只读脱敏预览，再逐项保存；全部默认不选；不恢复旧自动扫描 |
| 来源详情 | 模型/协议覆盖与重置、档位、Key池、价格、计费方式、预算、检测、删除全部有入口 |
| 轻量健康 | 明确许可与首次GET验证、冷却、未知、仅元数据；不改成无许可自动检测 |
| 模型池及建议 | 新建/编辑/策略/成员/删除保留；接受建议时重算，永久不用仍生效 |

来源行的“本月花费”使用该来源预算已经定义的服务器本地日历月，并显示时间范围；总览全局UTC窗口不能在这里无标识混用。关闭、预算阻断、额度暂不可用和健康未知用各自原因；不存在一个通用“错误=额度用完”标签。

## B104：任务页与菜单栏

任务页接已有提交、并行、互审、任务树、规则、评价和建议，不再造第二套任务簿或容量计数。单个任务、自动规则、模型/档位/cwd以及未支持的agent提示都保留。

- 真实只读执行注册表目前为空。多个agent模式保留说明和禁用状态，直到对应隔离路线完成；不能为了让新稿按钮可点就放开真实CLI。
- 任务树继续区分“已请求取消”和“清理已确认”；cleanupFailed不能被清历史或默认折叠隐藏。取消父任务仍影响已登记子任务，其他任务不受影响。
- 费用未知和部分计数必须保留。反馈规则在无评价时不出现，样本/费用不足时解释原因；接受建议仍重算并插在原规则之前，生成后可编辑停用。
- 保留任务输出、展开/收起、历史清理、规则增改删/排序/模拟匹配等现有入口，不因合成一个输入框而删除高级选项。

菜单栏复用相同的状态语义：活动与额度概览只显示已证明的在途外接活动、开启订阅及当前核心状态；订阅开关管理仍保留已授权但关闭的记录，方便重新开启，不能因概览过滤删掉原开关入口。一次性来源故障提示仍去重；普通的有效令牌数量只能标连接记录，不能直接当正在运行客户端数。

“全部退回原生”仍只停止应用实际拥有的核心/监督进程，并明确旧交互终端需自行关闭及撤销对应令牌。不能恢复按PID、端口或命令行标记查杀。未知/非零退出继续报告清理未确认。Swift源码可在云端修改，编译、截图和实际Mac退出流程由具备环境的一方验收；这一批不改正式B92图标。
