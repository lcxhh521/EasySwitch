# 差异化评审（2026-10-06）

用户的要求：借鉴 Magpie 和 opencodex 不能变成“长得一样”，要走出差异化。这里把界面、信息架构、功能逐项对一遍：相同的有没有理由，不同的怎么放大。

## 一句话定位

| | 一句话 | 对 agent 的做法 |
|---|---|---|
| Magpie | 每个 agent 的模型，一个地方（Every agent's model. One place.） | 改每个 agent 自己配置文件里的那几个键 |
| opencodex | 本地代理，让 Codex 等能用别家模型，带账号池和仪表盘 | 注入 / 改 Codex 的路由配置，Claude 桌面端有拦截模式 |
| EasySwitch | 你的 agent 调度台：任何来源进任何 agent，原生不动，agent 之间能互相派活 | 每次启动只用参数 / 环境变量 / 私有目录，**一个字节都不改别人的配置** |

## 逐项对照

| 方面 | 它们 | 我们 | 结论 |
|---|---|---|---|
| 改配置 | 写配置文件（Magpie 只改一个键并保留注释；opencodex 注入路由） | 从不改，靠每次启动的私有环境 | **根本不同，继续放大**（原则 2、3） |
| 原生与外接 | opencodex 默认整体切换；Claude 桌面端靠拦截 | 并排（Codex 目录、Claude Code /model），不拦截 | 不同，保持 |
| agent 互相调用 / 派活规则 | 没有 | MCP 互调、任务页、按规则自动分派 | **最大的差异点，产品重心** |
| 订阅当来源 | opencodex 有账号池和自动切换 | 每个订阅一个开关（新的默认关）、额度显示、用完自动换、预算 | 思路不同：由用户决定什么时候用 |
| 能力透明 | 没有 | 覆盖情况表：每个 agent 每项能力的真实状态和理由 | 不同，保持 |
| 手动配置向导 | 没有 | 给没有覆盖口子的应用（Trae、Z Code、WorkBuddy） | 不同 |
| 页面结构 | Magpie：Agents / Providers / Accounts / Usage + 菜单栏；opencodex：Dashboard / Providers / Codex Auth / Subagents / Models / Logs / Usage | Agent / 任务 / 模型来源 / 订阅账号 / 会话 / 用量 + 菜单栏 | “Agent 一行一个、选模型”这个骨架和 Magpie 相同，但它是用户问题本身的自然形状（agent 是主角），不改；我们多了「任务」「会话」两页，都是调度这条线的东西 |
| 菜单栏 | Magpie 有 | 有，面板里多了订阅开关 | 常见形态，有自己的内容，保持 |
| **界面色板** | Magpie 的设计变量 | 我们原来的 `--bg #f4f4f6`、`--line #e3e3e8`、`--accent-soft #eeedfd` 等几乎一样 | **没有理由相同，已改**：暖纸色底 + 青绿色强调色，深色模式配套，状态色和强调色分开（“开”不会像“选中”） |
| 文案 | 英文为主 | 中文、人话句子、不堆术语 | 不同，保持 |

## 已经做的

- 换掉了整套界面色板（`web/style.css` 头部的设计变量），不再是从 Magpie 取的值；去掉了样式文件里“借鉴自 Magpie”的注释。

## 还剩的建议（已登记）

- **首页重心**：Agent 页现在看起来仍像“模型切换器”，而差异点在调度。建议在 Agent 页顶部放一个一句话的“交给 agent 做点什么”入口（复用任务页的接口，选“自动”），让调度成为第一眼看到的东西（B65）。
- **图标**：第三方供应商图标集（lobe-icons 约 23 个、opencodex 的约 40 个）要换成自绘或字母头像（B33 的公开前清单）。
- **“会话”页的示意图**：布局是自己的，但可以再核一遍是否独立（B41 的后续）。
