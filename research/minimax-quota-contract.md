# MiniMax 额度接口后续方案（2026-10-08）

## 已核实事实

- 当前中国站FAQ给出 GET `https://www.minimax.cn/v1/token_plan/remains`，使用Bearer API Key；未给完整响应schema。套餐包括固定五小时窗口和周窗口，不应称滚动五小时窗口。[官方FAQ](https://platform.minimax.cn/docs/token-plan/faq)
- 同一FAQ说明Subscription Key也可以使用购买的余额，套餐额度用尽后可能自动由余额承担费用。因此“套餐剩余0”不能单独证明账号已经不能服务，也不能擅自理解为用户允许额外付费。
- 官方CLI的[已合并修复#175](https://github.com/MiniMax-AI/cli/pull/175)记录：`/v1/token_plan/remains`可用于`api.minimax.io`和`api.minimaxi.com`；旧的`/v1/api/openplatform/coding_plan/remains`曾返回需要cookie的应用错误。它证明旧域有相应实现依据，不能宣称旧域整体已停用。
- 官方CLI的[已合并修复#177](https://github.com/MiniMax-AI/cli/pull/177)记录`current_weekly_status === 3`表示不限额，`weekly_boost_permille`为倍率千分值（1500对应1.5倍），周剩余可能超过100%。这些修复进入[官方v1.0.17发布记录](https://github.com/MiniMax-AI/cli/releases)。这是历史实现证据，不是完整现行schema保证。

本轮没有核验固定版本的全部类型/测试文件，没有调用任何账号或实时额度接口。其余状态枚举、重置/倒计时单位、周边界时区、余额和模型资格字段、限流/403语义及新www域与旧API域响应的等价性仍未建立。

## 现有风险与已完成的窄修正

`plan-usage.ts`目前仍使用旧路径、旧字段解释，并把窗口读数交给通用额度路由。不能只改中国站预设域名就宣称完成迁移：这会失去现有主机匹配，也会把未验证的新结构交给旧解析器。

本轮只修正明确的本地解析问题：空字符串/纯空白不再经过Number变成0；真实零与非空有效数字字符串保留。无有效额度时保持未知，不制造耗尽证据，不覆盖先前有效观察。端点、路由、状态、重置和付费策略均未更改。

## 推荐实施顺序

1. 补齐版本固定的响应结构与合成样例，逐字段登记来源；不能用第三方猜测、空值补零或本地时钟推算替代证据。
2. 将“套餐内剩余额度显示”与“禁止继续请求的路由条件”分开。新解析器先做纯转换：区分有限、不限额、未知；保留boost和高于100%的合法值；无已核实时间就不显示确定恢复时刻。
3. 为已核实区域/接口分别建立读取器，拒绝重定向；不拿一个区域的Key自动试探其他域名。没有完整schema证据的域保持未接入。
4. 在切换生产路由前明确余额政策。建议默认避免自动额外消费；如果产品允许使用购买余额，必须由用户明确选择，并清楚说明本地估算预算不是厂商硬支出上限。不要因为套餐显示0就猜测余额存在，也不要因为可能有余额就自动继续收费。
5. 新预设、旧保存来源和额度读取器联动迁移。旧配置只给出可审阅的修正建议，不批量改写自定义地址、区域或密钥。

## 验收条件

纯/loopback样例覆盖：缺失/空白/非法数字、真实零、有限/不限额、boost及>100%、未知重置、不同区域目的地、拒绝跳转、非额度403、响应残缺、已存来源不迁移、未批准余额使用时不新增付费继续路径。最后仍需由用户安排真实账号与套餐验收；本轮没有以合成结果替代它。
