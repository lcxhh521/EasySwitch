# 任务评价与派活建议

完成任务后，可以展开“评价这次结果”，选择“好”或“不好”，也可以取消评价。评价只保存在本机，记录任务标识、选择和时间，不另存提示词或回答副本。没有评价时，规则区域不会新增建议卡片。

## 建议来自哪些记录

建议沿用已有规则的关键词、字数、文件夹和来源条件，不自动给任务另贴标签。只比较最近三个月内可核对的任务，并采用保守门槛：

- 每个候选至少五次有效评价，并且这些样本的费用都能完整归属
- 好评率至少八成，相比原方案不能下降超过五个百分点
- 档位一致、任务字数分布接近，中位和平均估算费用都至少低两成
- 已有相同目标的规则不会重复建议，包括用户已经停用的规则

这些是小样本的观察性比较，不能证明质量相同、任务难度相同或未来一定便宜。没有足够证据时只说明缺什么，不生成规则。

点“生成这条规则”时会重新检查依据。规则放在原分类规则前面，否则原规则会先匹配；生成后仍能编辑、停用或删除，不会自动替你执行任务。

## 费用如何归属

任务费用使用服务器签发会话与任务之间的精确对应，包含登记的子任务，不按程序名或时间窗口猜测。每次模型请求、重试、流尾和子任务都结束，且来源提供完整有效的用量时，才可作为价格比较证据。

断流、取消、缺少协议结束标记、缺少计数、订阅月费、缺少价格或当前计费映射未覆盖的项目，都会保留“费用未知”。一次失败后重试成功不会抹掉之前的不确定性；账本仍保留网关已经观察到的部分用量和费用；内部换 Key 或兼容性重试中未观察到的尝试不会被猜成零价。预算使用自己的耐久账本，这个归因簿只服务任务展示和建议。

本机归因簿最多登记五千个任务，包含子任务。这是总登记容量，不是自动滚动窗口；达到后保留旧记录，新任务费用未知，不再参加价格建议。不会为了腾空间自动删掉或改写旧任务树。

记录损坏或无法保存时，不把旧值当作零价。若连故障标记也无法保存，界面会要求暂停派活并检查磁盘；不要通过删除账本来恢复所谓“正常”。进程重启恢复和故障处理经过假环境验证，不代表已经验证突然断电时的磁盘同步保证。
