# Antigravity 运行时客户端配置

此来源仍属于未完成真实账户验收的兼容路径。当前文件树不再附带 OAuth 客户端 ID 或客户端密钥；历史私有提交不改写，也不能把整个私有历史用于公开发布。

## 配置边界

只有用户明确指定 `EASYSWITCH_ANTIGRAVITY_CLIENT_CONFIG` 时，登录或刷新才会读取该绝对路径。程序不搜索原生应用、登录目录、钥匙串或其他文件来寻找客户端身份，不创建配置，不复制旧常量，也不提供内置后备。没有配置时，在打开浏览器、监听回调或读取刷新令牌之前拒绝。

配置格式是版本为 `1` 的 JSON，对象只允许 `version`、`clientId`、`clientSecret` 三个字段。两项身份字段必须为非空、无空白控制字符的字符串。文件限 16 KiB、当前用户所有、group/other 无权限，建议使用 0600。拒绝末级文件符号链接、目录、共享权限和读取期间变化的文件；父目录是否含符号链接不在检查范围。该检查针对 POSIX 文件权限；没有完成 Windows ACL 验收。

这里不提供真实身份值，也不会指导从别人的客户端提取身份。配置与登录仍需用户确认其使用资格及服务条款；原生应用格式的自动读取器尚未实现。已有来源和刷新令牌不会自动删除，但必须显式提供有效运行时配置后才能继续刷新。改变客户端配置会让内存访问令牌缓存失效；移除账号会使在途刷新失效，迟到的响应不能重新填入缓存。取消或超时会中止网络阶段，已经开始的凭据写入则等待同账户串行恢复后才报告取消，恢复失败会明确提示检查密钥存储。

## 网络与兼容性

OAuth 授权、令牌交换和用户信息使用固定 Google HTTPS 目的地；模型调用和项目发现使用固定 Cloud Code Assist 目的地，不允许配置任意主机或请求头。所有带凭据的 HTTP 请求拒绝重定向。仅 Node 测试进程中，显式开启假服务开关才允许 literal loopback 地址覆盖。

来源事实：

- [Google OpenID Connect 元数据](https://accounts.google.com/.well-known/openid-configuration)列出授权、令牌及用户信息端点
- [Google 官方 Code Assist 客户端源码](https://github.com/google-gemini/gemini-cli/blob/main/packages/core/src/code_assist/server.ts)公开 `cloudcode-pa.googleapis.com` 与 `v1internal` 协议事实

这些资料不证明某个 Antigravity 账户可直接使用该路径。此版不伪造已安装 IDE 版本，发送 EasySwitch 自己的 User-Agent；回调使用系统分配的 loopback 端口。原生应用特定端点、身份、授权范围、回调与套餐兼容仍未验收；配置存在不能等同于来源可用。

## 已验证范围

只执行合成配置、注入读取器和 loopback 假服务测试，覆盖缺配置零副作用、文件边界、缓存身份变化、默认关闭、登录/刷新及四协议兼容路径。令牌、用户信息和项目接口的重定向都验证不会把凭据发送到第二个假服务。没有配置、读取或发送真实凭据，没有打开真实浏览器登录或调用真实模型。
