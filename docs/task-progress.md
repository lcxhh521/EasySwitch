# 任务进度与取消

任务页显示正在执行的任务树、agent、模型、已用时间和已记录的估算费用。父任务和子任务分别保留记录；父任务费用可能已包括子任务，不能把两行再次相加。缺少完整用量、请求尚在结束或清理失败时，费用明确标为未知，已记录的部分估算仍可显示。

点击“取消”会先把该任务及已登记子任务标为已取消，撤销各自签发的网关令牌，再等待对应执行过程结束和清理。等待期间显示“正在清理”，不会因为运行计数变为零就停止刷新。取消之后不能用旧父任务再创建子任务或签发新令牌；其他任务和用户另外签发的会话不受影响。已经进入供应商的请求可能已产生费用，取消不能撤销既有用量。

只有记录过所有权的进程可以被结束。后台任务在支持进程组的平台创建自己的进程组；退出时先请求终止，超时再强制结束，仍不能确认时报告“清理未确认”。不会按端口、程序名称或命令行标记猜测并终止其他进程。旧式交互终端不保留可验证的进程句柄，需关闭对应窗口并在 Agent 页撤销其会话令牌。

MCP 子任务使用发起请求时的已鉴权会话确定父任务和深度，不能用请求正文伪造父子关系。取消会给调用方明确的取消结果。任务深度和共享并发上限保持不变。

## 退出与恢复

核心服务退出会请求取消自己的任务，并等待清理。应用外层监督器留出足够的任务退出时间；核心非零退出或超时不会被显示为成功停止。未确认清理的任务保留在记录中，不能通过“清空已完成”隐藏。请先检查本机进程和会话状态，再恢复工作。

任务开始和终态仍写入同一任务记录文件。重启前没有完成的任务显示为已中断或取消，费用保持未知；应用不会根据历史 PID 重新取得进程所有权，也不会恢复执行中任务。

## 验证范围

本地测试使用注入的进程、时钟和 loopback MCP 服务，覆盖父子取消、等待进程关闭、独立任务不受影响、精确令牌撤销、重复操作、失败清理和任务树展示。没有运行真实 agent、真实模型或用户凭据。macOS 的实际进程组、客户端行为、菜单栏编译与整机退出仍需单独验收。
