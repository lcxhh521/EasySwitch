# 价格表的分阶段更新

当前内置金额仍使用旧参考表，界面已明确标为“未按官方现价复核”。这次没有改用户自填价格、历史账本、预算判断或任务建议，也没有把新表悄悄设成默认。

## 现在有哪些结果

新的官方事实文件只覆盖十个明确模型标识，共十七种价目。每条保留官方链接、核查日期、计费币种、上下文区间、地区、缓存条件及未知字段。新生成器只读取明确指定的事实文件，不扫描其他应用目录、不访问网络；缺失价格保留 `null`，不会补成免费。

当前新估算器中，只有 GPT-4o 和 GPT-4o mini 的普通文本条件可直接匹配；调用者仍须证明是对应官方直连、标准服务和非区域加价范围，传入真实完整用量。新估算器暂未接入生产记账。其 complete 只表示所选普通文本 token 类别齐全，不包括厂商工具、图片/音频、税费或合同价；未来任务费用比较还必须另行证明整次请求的收费范围，不能直接复用这个布尔值。

其他八个模型的价格事实已经记录，暂未自动选择条件。原因分别是整个会话的上下文、实际推理地区、缓存创建数量和保存时长，以及峰谷期的节假日规则。源码能可靠证明这些条件时，应支持对应价目；缺少证据时才显示未知，不能用一个方便的默认值代替。

## 为什么没有立即替换旧表

旧表有 1,233 条模型记录，涉及二十五个供应商和二十二个主机映射；新事实只核查首批十个标识。立刻替换会使大量费用变为未知，影响预算警告和任务价格比较。保留旧数字也有局限：它们可能过时，只能作为参考估算。例如 [DeepSeek 当前价目](https://api-docs.deepseek.com/quick_start/pricing/)已有峰谷及节假日条件，旧表中的单一价格不能当成当前官方账单。

| 项目 | 本批状态 | 下一阶段拟采用的规则 |
| --- | --- | --- |
| 用户自填价格 | 继续优先 | 继续优先，明确这是用户提供的估算 |
| 旧参考表金额 | 数字完全保持，增加旧表标签 | 可保留参考金额，但不能把未复核的价格当成已证明完整费用 |
| 官方直连 | 新表与纯计算器独立存放 | 条件和用量均可证明时使用对应官方价 |
| 中转站 | 当前旧逻辑未切换 | 不因模型名称相同就套原厂售价；需要中转报价或用户输入 |
| 订阅 | 继续不估算单次账单 | 仍不把订阅额度或月费当按量价格 |
| 历史账本 | 不重算、不改写 | 新记录另存适用价格来源及版本，旧记录保留原估算口径 |
| 预算和任务建议 | 当前算法未变 | 部分已知金额与未知次数并列；证据不足费用不参与价格优劣建议 |

预算始终是本地估算，不是供应商账单硬上限。未知费用不能证明实际支出未超过预算。下一阶段需要先展示迁移影响，再启用相应行为，避免原本可用的设置在一次表更新后悄悄改变。

## 后续实现顺序

1. 先补稳定、可观测的普通文本条件。通过原始请求及最终响应确认服务档位、实际地区、缓存计数；不能仅用默认工作区设置或来源名称猜测
2. 将确定的条件压成最小计费元数据，例如价目ID、事实版本、用量类别及完整性。无需额外保存请求正文、工具参数、账号或凭据
3. 按实际出站来源和精确模型选择价格。会话级长上下文、缓存存储和节假日日历需要单独证据与测试；不凭一条请求的输入量解决所有条件
4. 并行计算旧/新结果的覆盖与差异，使用本地合成数据验证迁移，不进行真实模型调用。分开显示“旧参考”“官方条件已满足”“部分费用”“未知”
5. 最后切换新记账，并使预算和任务建议消费价格完整性。既有用户自填价及历史记录保持清晰的原始口径

最低测试包括：上下文临界值、币种不混算、未知缓存不补零、缓存写入不重复计费、官方主机与中转区别、模型别名不猜测、地区/服务档位未知、部分金额保留、历史账本不重写，以及预算和建议对未知成本的处理。

## 可重复生成

在项目根目录运行：

```sh
node scripts/build-prices.mjs core/src/pricing/official-facts.json core/src/pricing/official-prices.json
```

本阶段生成器会拒绝覆盖仍在运行的旧 `prices.json`，避免把新格式误写成旧运行时表。生成表记录事实文件原始字节的 SHA-256。这个摘要用于判断生成物是否对应输入，不是官网网页的存档摘要，也不代表价格永不变化。公开价格核查不读取账号、发起模型请求或验证实际发票。

## 离线迁移对照（2026-10-08）

第四步已有一个独立的合成数据工具；它不表示前面三步的生产元数据采集已经完成。运行：

```sh
node scripts/compare-pricing.mjs core/test/fixtures/pricing-migration.synthetic.json
```

命令只读取显式给定的fixture和仓库自带价目，结果写到标准输出；没有默认输入、目录扫描、HOME查找、网络、真实模型/客户端或文件写入。导入脚本不会执行CLI。旧端复用现有 `ratesFor` / `costOf`，新端调用暂存的官方估算器；既有生产调用方完全不接这个报告。

输入必须显式标明 `schemaVersion: 1`、`dataKind: "synthetic"`，每条提供独立ID、模型、来源地址、计费类型和用量。普通文本scope及缓存计数缺失时不猜测。可提供 `userRates` 验证用户覆盖行为。模式、ID及URL字段都只用于计算，绝不用于连接来源。`synthetic`是调用者声明，不是脱敏保证；只使用制造的案例ID和非私人模型名，不要输入真实请求、账号或秘密。报告会回显案例ID和模型名。

报告分开保留：

- `baseline`：旧参考金额、用户自填估算、未知或订阅；缓存缺失时明确标出旧计算器曾补零的假设
- `staged`：所选文本token类别完整、部分价格、未知或订阅；`factId`指回带官方链接和核查日期的事实，缺失金额不补0
- `comparison`：仅旧参考与完整的所选文本类别金额可比较，差额为新减旧，单位USD；用户价不被官方价替代、不参加差额，订阅没有单次账单金额。非USD候选不换汇、不与USD混算
- `summary`：仅同一可比子集汇总差额；部分已知金额另列。没有可比样本时是`null`，真正零用量时才保留0；不生成把未知费用当零的“总账单”
- `provenance`：输入fixture及官方事实原始字节SHA-256、核查日，以及对已解析旧表执行`JSON.stringify`所得UTF-8字节的SHA-256。旧表摘要不是原文件字节摘要；两个价目摘要都不是官网快照

检查过的21个样本覆盖两种当前可选的OpenAI模型、另外八个条件模型、用户价、中转、别名、缺失缓存/地区/scope、无效用量、订阅、未知模型、零用量及缓存写入。当前5条显示所选文本类别完整，其中1条用户覆盖不参与差额；4条可比样本的差额为0，15条官方结果未知，1条订阅。这个0只能描述这4个合成样本，不能说明1,233条旧记录或实际流量已完成迁移。部分价格和CNY不混算另有合成价目回归，未伪装为现有官方表已支持的新价目。

所有报告固定标注 `wholeBillCoverage: "not-established"`。fixture中的条件是合成断言，不能证明生产请求的真实地区、服务档位或其他收费；本工具不接入、不回写历史账本、预算或任务价格建议。B33仍需完成真实可信元数据、更多价目条件、迁移策略及其余公开前工作。
