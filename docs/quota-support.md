# 订阅额度显示与来源切换

额度数字只能来自对应来源实际返回的报告。没有报告、格式不认识或读取通道尚未接入时，显示未知；登录成功不代表已读到剩余额度。模型请求的输入输出 token、账单费用、并发限制和订阅剩余次数不是同一种数据，不能互相换算成剩余额度。

## 当前范围

| 来源 | 当前依据与实现 | 尚未完成的部分 |
| --- | --- | --- |
| ChatGPT / Codex | 网关读取已经经过的回答中的用量响应头，保存窗口百分比和恢复时间；不额外调用额度接口 | 响应没给的窗口和恢复时间未知；当前记录只在内存里 |
| GitHub Copilot | 已按官方 SDK 的 `account.getQuota` 合同实现纯快照解析、格式化和明确的未接入状态 | 尚未接入 SDK 额度读取；生产界面不能据此显示猜测数字，也不会借用现有直连 token 去调用私有额度接口 |
| Kimi Code | 保留已有额度读取器；模型请求现可区分官方明确的额度耗尽与其他拒绝 | 现有读取器来自兼容性研究，真实账号和新旧套餐响应变体未验收，不能把缺失字段补成满额 |
| MiniMax | 保留已有读取器；官方页面另提供套餐查询入口 | 当前旧读取路径与官方页面新入口不同；尚未核实新入口响应字段，不自动切换凭据接收地址或宣称已兼容 |
| 其他订阅 | 沿用各专用适配器已有的失败和限流处理 | 无公开且已接通的额度合同就不显示剩余数字；不能从账号名称或月费推算 |

所有新增验证使用构造数据和本地假服务，没有读取真实账号凭据、运行厂商 CLI 或调用厂商额度/模型接口。

## Copilot：官方合同不等于已连接

[GitHub 官方用量说明](https://docs.github.com/en/copilot/how-tos/copilot-sdk/features/usage-and-billing#account-quota-and-premium-interactions)提供 SDK 账户查询 `account.getQuota`。结果中的 `quotaSnapshots` 按种类分开：`premium_interactions`、`chat`、`completions`。解析器只接受这些已知类别及对应数字、日期；未知类别、原始账号字段和任意错误文本不会进入展示。

`entitlementRequests` 为 -1 时，只能说该项不限次数，不能推断其他类别、模型权限或速率限制也无限。缺失的 `remainingPercentage` 和 `resetDate` 保持未知，不按套餐名称、次数或当前月份猜测。此模块没有 SDK 运行时依赖，也不参与模型池可用性判断。

[GitHub 账单用量 API](https://docs.github.com/en/rest/billing/usage)按账单归属提供消费记录；个人、组织、企业的适用范围不同。这类已用量报告本身没有足够信息推导账户当前剩余额度，因此不替代账户额度查询。

## Kimi：额度拒绝与并发拒绝分开

[Kimi 官方错误参考](https://www.kimi.com/code/docs/en/kimi-code/error-reference.html)明确区分五小时、旧套餐周额度、月度额度和并发请求限制。它们可能同样返回 403，不能只看状态码。

新增分类器只在明确的 Kimi 通道识别文档列出的三类额度耗尽文案；认证失败、权限拒绝、并发请求限制和其他 403 均不视为额度用完。保留原状态码，只更新已有模型池的等待信息。文案没有给出准确恢复时刻，就不能从“五小时”或“月度”推算窗口起点。

## MiniMax：端点与响应格式分别验证

[国际站套餐说明](https://platform.minimax.io/subscribe/token-plan)与[国内站套餐说明](https://platform.minimaxi.com/subscribe/coding-plan)公开列出各自 `www.minimax.io` / `www.minimaxi.com` 主机上的 `/v1/token_plan/remains` 查询入口，使用用户提供的 API Key。公开说明没有在本次核查中给出可确认的完整响应字段合同。

现有读取器使用另一条旧路径，保留不代表新合同已验证。本轮没有向任一入口发送请求，也没有通过第三方样例猜测新字段。

## 自动切换的边界

已配置模型池可以跳过已知耗尽的成员，按现有规则尝试下一个来源。直接指定来源的请求不会擅自换来源，因为备用选择规则尚未确定。来源开关仍是开/关二态。

厂商未提供恢复时间时，当前实现有三十分钟的本地等待，界面显示“后可重试（恢复时间未知）”；它只是下次允许重试的时间，不是厂商确认的恢复时刻。只有已耗尽窗口明确报告的重置时刻才显示为恢复时间。具体额度以官方界面为准。
