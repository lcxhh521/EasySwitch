# 已确认名单内的自动选来源（B123，P0）

## 使用与当前限制

在 Agent 的已选固定模型旁点“自动选来源（仅纯文字试用）”，复用现有同名建议查看有限来源及每个来源的固定 Key 标签，显式确认后一次保存模型池和该 Agent 的主模型绑定。不会启动程序、登录、探测或调用模型。来源可能属于不同账号；同名也不证明模型能力相同。

这是可选的 `automatic` 策略，不迁移旧 `order` / `rotate` 池，不恢复派活、后台任务或手动调度界面。没有可信失败证据时保持用户原选来源优先，其余按所确认顺序选择，不需要另配池顺序。

P0 仅支持普通 HTTP 来源的无状态纯文字请求。Chat、Responses、Messages、Gemini 的原始请求体采用严格字段白名单；工具、图片/音频、opaque continuation、原生签名、未知字段/能力和需要专用鉴权的订阅/CLI来源拒绝，提示使用固定来源。不承诺 Claude Code / Codex / OpenCode 等常用工具型会话已适合此模式。普通固定来源及旧池的工具协议能力保持原样。入口、确认前、绑定后的 Agent 卡片以及复用已有自动池的模型选择项都提示该限制；需要工具时，在同卡片“主模型”选择器选回固定来源，下次启动使用新设置，不自动替换正在运行的会话。

## 确认合同

- 同名匹配只是候选提示；用户必须核对具体来源、模型及固定 Key。最多32个不同来源、至少2个。当前优先来源排首位。
- 有 Key 池时固定首个已启用 Key；没有 Key 池字段才允许旧单 Key。空池、全部禁用或缺少该 Key 均拒绝，不从旧单 Key 或其他 Key 偷换。
- 确认绑定完整来源/端点/模型/计费与实际路由配置、配置代次、固定 Key 身份及其内容签名。配置或应用内凭据写入/删除（包括同值保存及失败写入前的已落盘失效）让旧确认失效；不把 providerId/keyId 当作账号身份证明。
- 外部直接修改密钥库，只能在读取发现时失效，无法原子保证外部多 Key 修改与网络发送。已发现的内容变化/删除会持续使旧确认失效，恢复原值也必须重新确认。每次实际发送前重读所选 Key，比对原固定值，无法重读就拒绝，不把新值偷偷写入已准备的请求。
- 持久化失效失败时当前进程保留失效代次并拒绝；不声称磁盘写入失败后仍有跨重启的持久保证。修复本地存储并重新确认后才使用新池。
- 确认令牌只在进程内保存，5分钟过期、最多64个；它不是凭据。取消不保存，刷新不能恢复权限。幂等重试只核对同一次确认，不覆盖用户后来改选，包含改成 B 再改回 A、同值显式保存和 profile 替换。
- 预览、确认、幂等结果在最后一次异步检查之后仍同步检查配置及绑定代次。新池与绑定一次落盘；失败回滚，不留下半份模型池。
- 公共 API/UI 不返回 Key、salt、凭据签名或配置签名。内部签名不能直接用于上游认证；历史账本与原生配置不迁移、不删除。

## 派发与失败恢复

- 只使用本次固定身份及入站协议下、真实推理 HTTP 响应的短期负证据：401/403/429/5xx 等待60秒。没有观测/到期/未知状态均为未知，不当作健康、额度充足或免费。成功不会清除另一次有效失败事实。
- 旧 providerId 额度、旧池休息标记、模型列表探测成功、请求时长和价格缺值不参与择优。路由能力变化使确认失效，因此不同出站配置的旧失败不沿用。
- 全部可选来源处于等待时返回暂停，实际推理调用为0。标记到期仅允许下一次用户请求重新尝试，不代表真实额度恢复；不做后台探测或定时重试。
- 每个逻辑请求最多2次实际推理 HTTP 请求。池备用、固定 Key 和适配器 max_tokens 修复共享计数；修复已耗尽2次时不再尝试备用。重定向禁止跟随，不借重定向增加隐式发送。
- 每次派发前重核完整已确认名单、所选固定 Key、当前会话、全局预算及来源预算。最后一次 await 后同步重核本地代次/预算/撤销，再计数和发送，期间没有 await。
- 仅未输出、未取消、有剩余次数、且确实收到可重试上游 HTTP 状态时允许换来源。局部输入/鉴权/预算失败、网络异常或取消不伪造成来源额度事实。已输出或连接取消不重放，不“无损续写”。
- 备用仍可能收费，两次都可能计费。现有预算是基于已知计量的估算守卫，不是厂商账单硬上限，也不预留并发金额；本批不提高预算、不增加费用权限或新凭据。

## 验证边界

只进行隔离 HOME、内存密钥、fake/VM/loopback 的受控测试。独立复核包含绑定 ABA、异步撤销、Key变化、预算、跨层次数、重定向、输出后取消与间接 fallback 守卫。实际数字以本批交付记录为准。

未运行真实账号/模型/客户端、Mac Keychain、真实浏览器 DOM/窄屏或打包验收。没有创建 workflow、调用收费 runner、推送、合并 main、发布或部署。云端本地源树没有物化原 AppIcon.icns，未来提交必须保留其原 blob，不得用缺文件的树替换远端。
