# CLI configuration and MCP gaps: cloud-only validation

Date: 2026-10-06. Scope: B2/B3/B4 configuration gaps, with no real agent, account, login, model request, or installation. The implementation uses Node built-ins and adds no runtime dependency. No third-party implementation was copied; the links below establish configuration/protocol facts.

## Implemented

- **dsh:** private patch registers every selected main/child/title/compaction model, writes model-owned `reasoningEfforts`, and applies `agent-default-model.reasoningEffort`. `none` maps to dsh's `off`, with wire spelling `none`. A selected main level alone is a narrow fallback when model capability data is unavailable; it never advertises every level for every model. The current official schema rejects off-only maps, so switching off requires capability data with a real active level. An empty known capability list produces `reasoningEfforts: false`.
- **dsh tiers:** `subagent` writes `tool-subagent.agentOptions` while retaining `provider: spawn`, `toolName: subagent`, and `backgroundMode: continuable`. The child's effort is not blindly copied from a different main model. `small` supplies title and compaction defaults; `title` and `compaction` individually override them. Title patches retain all five required size/timeout settings.
- **dsh MCP:** inserts the official `@deepseek-ai/dsh-mcp-client` using Streamable HTTP and exact auth/depth headers. Before launch, EasySwitch locates an already-installed package from the executable's installation or existing `$DSH_HOME/profiles/node_modules`, reads its manifest, and creates one symlink beneath the throwaway home. It does not install packages or run `dsh plugin add`. Missing packages fail with an actionable error; no global profile is modified. Linked destination ancestors are rejected. Launch-spec generation remains pure, so capability inspection does not prepare or run a plugin.
- **Kimi Code:** supports current TypeScript `@moonshot-ai/kimi-code`, not the archived Python executable's different config. Corrected headless form to `--model <alias> -p <task>`, private `KIMI_CODE_HOME/mcp.json` HTTP attachment, and `[secondary_model]` for the subagent tier. Shell model/custom-header overrides are cleared. Model capabilities and supported efforts are derived from supplied model facts rather than unconditional low/medium/high claims.
- **OMP:** private `mcp.json` uses explicit `type: http`; `--config` applies the private settings as a one-shot overlay. Named profiles, extra overlay files, external Claude-config opt-in, and ambient model-role overrides are cleared. The overlay disables project MCP discovery and foreign user providers. Model effort declarations now include the actual selected/known levels instead of a contradictory fixed low/medium/high list.
- **AtomCode:** private `$ATOMCODE_HOME/mcp.json` with URL and headers; effort-list generation is model-owned. The official implementation supports this HTTP form.
- **CodeBuddy Code:** the older handoff's “no endpoint” conclusion is superseded by current official docs. Added a private `CODEBUDDY_CONFIG_DIR`, `CODEBUDDY_BASE_URL` for the Anthropic-compatible endpoint, `-p` tasks, own effort flag, and small/reasoning/subagent model overrides. Explicit user-only setting sources read the private settings file; strict MCP loads only the generated HTTP entry. Inherited platform auth, custom headers, shell env-file, unsafe sandbox marker, replay/record paths, and regional service selection are cleared. No auto-approval option is enabled. This describes the CLI; the WorkBuddy GUI still has its separate manual configuration route.
- **Trae Agent:** complete private YAML config, verified `--config-file`/`--trajectory-file` arguments, an OpenAI **Responses** provider, optional Lakeview small-model routing, and a stdio MCP attachment using EasySwitch's bundled bridge. The official config exposes HTTP fields but the actual MCP client throws `NotImplementedError` for them; direct HTTP config would be a false implementation.
- **Authentication integration:** Codex custom-provider config uses `env_key="EASYSWITCH_GATEWAY_TOKEN"`; both launch forms supply the issued token. Hermes main/delegation configs reference `${EASYSWITCH_GATEWAY_TOKEN}` and do not persist the token itself. Headless sessions issue scope/depth-aware tokens and revoke them on completion, cancellation, or config/materialization failure. The session directory is cleaned on each of those paths. Timeout now escalates from SIGTERM to SIGKILL after three seconds.
- **Remote Gemini/Copilot reconciliation:** retained Gemini `thinkingConfig.thinkingLevel` and Copilot's private `effortLevel` file when a level is requested, together with their explicit uncertainty/runtime-unverified caveats. Added a pure configuration regression; this does not establish real-client support for those inferred settings.

## MCP bridge boundary

`core/src/mcp-stdio-bridge.ts` translates newline-delimited JSON-RPC requests and notifications to EasySwitch's existing stateless JSON-over-HTTP endpoint. It starts no tools or agents itself. Generated launch configurations pass credentials through the child environment, not command-line arguments or error messages. The remote `bin/es-mcp-stdio.ts` entry is preserved as an import-safe wrapper around this module; historical explicit URL/`--header` arguments remain accepted for compatibility, but new Trae configurations use environment credentials.

- Only `http://127.0.0.1|localhost|[::1]:PORT/mcp` is accepted, without URL credentials, query, or fragment
- Redirects are rejected rather than forwarding credentials
- Input and response bodies are bounded (default 4 MB), and requests have a timeout
- Request IDs and JSON-RPC envelopes are checked; notifications receive no replies
- Failures return a safe generic error and never echo HTTP bodies, auth headers, or URLs
- A finite SSE response containing exactly one JSON-RPC reply is supported with the same timeout/body bound/ID validation; this preserves the remote compatibility test
- This adapter is not a general remote MCP proxy: no long-lived SSE, server-initiated messages, session resumption, or batch framing

- `core/test/mcp-stdio.test.ts`: retained the remote JSON/SSE/header/notification and actual EasySwitch MCP server intent using in-process streams plus authority-issued tokens; added environment/legacy-argument parsing checks. No child process or installed agent runs
- `core/test/verify-launchers.test.ts`: pure flag extraction plus an injected help runner covering stdout, nonzero stderr, top-level fallback/cache and unavailable help. No fixture executable is created or started; the production CLI verification command is not run by these tests

The remote dsh integration retains the `dshMcpPlugin()` compatibility export and supports `EASYSWITCH_DSH_MCP_PLUGIN` only when it names an absolute path with the expected package manifest. Invalid explicit overrides do not fall back to another installation. The unrestricted generic link writer is not used. Historical remote acceptance recorded MCP tool visibility and title calls on the small model, not child-agent execution; the newly combined private preparation remains runtime-unverified.

Run these only with a temporary HOME and the local guard, or use the audited `npm run test:local` whitelist after adding the files. The guard blocks all subprocesses and non-loopback fetches. These tests never run an agent binary. `agent-launch.test.ts` contains historical real-client tests and is not the verification entry point for this task; only its stale dsh capability assertion was updated. Future-client fixture sources in `codex-e2e.test.ts` and `mcp.test.ts` were also repaired to issue scoped tokens, pass the Codex gateway env key, revoke tokens, and clean up temporary directories. Those files were typechecked, never executed.

## Integration and remaining acceptance

`LaunchInput.modelEfforts?: Record<string, string[]>` should contain all main/tier/pool model capability lists, keyed by exposed `<provider>/<model>`. The server owns computing that map from its catalog and pool intersection. These new features must remain **documented, runtime unverified**, even where the historical dsh base launcher has `verified: true`.

Real-client acceptance remains open for all changes. Kimi and AtomCode also permit project-level MCP entries to override a same-name user entry; their private user config alone is not a claim that project config is disabled. dsh packaged-runtime module resolution varies by version and needs real-host acceptance. Trae's default tool set includes file editing and shell commands; EasySwitch does not claim it is read-only. A stdio bridge test proves the bridge protocol, not the Trae host's complete execution behavior. No broader B2/B3/B4 completion or subscription access is claimed here.
