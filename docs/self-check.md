# 自检与错误提示

控制台的“自检”和 `es doctor` 默认只读取已有状态：网关是否响应、钥匙串小程序健康信息、来源以前的检测结果、程序安装记录、会话有效期、预算状态和最近的失败类别。不会读取 Key、发模型请求、执行 Agent 或自动登录。`es doctor` 在服务未运行时只报告问题，不自动启动后台服务；`es doctor --json` 输出结构化报告。

来源没有检测过、程序安装没有记录或帮助参数尚未检查，会显示“尚未检查”。钥匙串签名缓存尚未建立或文件变化时同样显示待确认；被动自检不会为了刷新它运行签名检查程序。历史检测通过不保证现在仍然可用；没有失败记录也不等于完成了真实验证。

## 主动检查

每项主动检查都需要单独选择并勾选确认：

- “检测这个来源”可能产生模型费用，沿用来源检测流程。来源关闭、暂停预算启用、密钥库不可用或来源不支持通用探测时，会先拒绝，不绕过限制
- “检查启动参数”会运行所选程序的帮助命令。它可能读取自己的配置或登录状态，因此需要明确同意；帮助列出了参数，也不能证明真实启动、目录隔离或模型调用已经通过

检查有单项和整批等待上限，支持取消。取消后不继续执行后续项目；已经完成的检测记录可能已经保存。这里只管理自己的检查，不停止普通 Agent 会话。

修复按钮会导航到相应设置或显示操作说明。钥匙串构建必须在自己的 Mac 前台完成，并使用已有签名身份；自检不会创建证书、代替签名、自动登录或取消预算。详见[密钥存储说明](native-keychain.md)。

## 错误如何显示

常见错误统一说明发生了什么、可能原因及去哪里处理。技术状态只放在折叠的“详情”中；不会把任意上游报错、程序输出、Key 或令牌当作提示正文。无法可靠分类时会给通用检查建议，不猜测具体原因。

控制台 API 保留错误状态和常用字段结构，错误正文使用固定安全文案；消费者应使用规范错误类别，不依赖旧版完整英文异常字符串。模型原生协议直通不受这项控制台文案调整影响。
