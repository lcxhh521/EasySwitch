# 来源轻量检查与备用模型

普通 HTTP 来源可以开启“允许定期读取模型列表”，再点击“检查一次”。默认关闭。首次检查只有返回有效的原始模型列表，才会启用周期检查；失败或无法确认时保持“状态未知”。开启检查不会发送生成请求，也不会用模型回答来探测来源。

检查使用 GET 模型列表，反映这个元数据端点的最近状态。它不验证推理、工具、流式输出或模型额度，也不能保证厂商永不对元数据请求计费或限流。普通中转来源需要明确许可；订阅专有适配器、CLI 来源、Vertex 以及未支持的模型列表端点不会自动套用这一检查方式。

## 频率、恢复和提示

- 同一来源至少间隔五分钟，整个服务最多同时检查两个来源
- 连续三次明确失败，才标记模型列表检查不可用；本地凭证读取异常、无法识别的响应等保持未知
- 收到限流响应会退避，并遵守 Retry-After；切换开关或重复点击不能缩短已知冷却
- 限流不等于套餐额度耗尽，模型列表成功也不代表额度已经恢复
- 来源地址或鉴权配置改变后，旧验证失效；重新检查成功才更新验证事实
- 过期结果回到未知。一次故障只产生一次状态提醒；恢复后可产生新的恢复提示，失效或删除来源的旧提醒会丢弃

“下次可检查”表示手动检查也需要等待的时间。来源关闭时不检查。应用重启会重新获取当前健康状态，保存的端点验证指纹不被当作“现在正常”的证明。

## 每个 agent 的备用模型

备用模型需要明确设置。普通直连请求开始前，如果已知主来源的模型列表连续检查失败，或现有网关记录表明来源额度尚未恢复，可以选择备用模型。未设置备用、主来源健康未知且没有已确认的额度耗尽证据、备用已关闭或不可用时，保持原有请求行为。

选择发生在请求发送前。本次请求才遇到的失败不会自动重放到备用；已经开始输出的请求也不会重放。模型池继续使用自身的成员选择和故障切换，原生请求不会因为这一设置改为外接模型。这里使用明确的直连模型名，不把模型池再套入备用链。

换用备用不改写主模型绑定。后续请求恢复主来源时会按主模型发送；任务、会话和网关记录显示实际使用的模型和换用原因；控制台关联最多最近两千条换用记录，每个任务或会话显示最近二十条，完整历史仍在本机用量账本。主、备用模型的能力和价格可能不同，设置时应核对。正常预算限制继续适用。

## 验证范围

本地假环境覆盖停机信号、恢复、额度标记、未知状态、并发、取消、配置变化、冷却和输出开始后的禁止重放。界面测试验证默认关闭、未知状态文案、冷却按钮和来源文本转义。没有使用真实模型、真实账号或真实凭证，也没有据此宣称所有厂商的检查都免费或不会触发限流。
